# 改动说明：帧回传 文件 → 共享内存（v3）

> 目的：消除 B1 子进程模式显示回传里"每帧写文件 + 读文件"的开销，改善滑动/输入的跟手感（与 CPU 快慢无关的那部分卡顿）。
> 影响面：仅显示回传通道；CPU/图形/存储路径不动。失败自动回退旧的文件协议，可安全灰度。

---

## 1. 改了什么

B1 模式（QEMU 跑在子进程）原来靠**文件握手**回传画面：

```
App 写 <dir>/frame.request → QEMU 子进程截图 → 写 <dir>/frame.rgba(.tmp→rename)
                          → 写 <dir>/frame.seq → 删 frame.request
App 轮询 frame.seq → 读 frame.rgba → 上传 GL
```

每帧：写端 `open/write/rename`（3 次系统调用）+ 读端 `open/read`（2 次），再加文件页缓存与该目录 dentry 抖动。1080p 一帧就是几 MB。

现在新增**共享内存通道**（首选），失败回退老路径：

```
QEMU 子进程建 <dir>/frame.shm（mmap）→ 把最新帧 memcpy 进轮转缓冲 → release 递增头里的 seq
App mmap 同一文件 → 按 seq 变化，直接把该槽指针交给 glTexSubImage2D（零拷贝，读端不再 memcpy）
```

`frame.request` 仍是"要一帧"的控制信号，两条路径共用。

## 2. 同步协议（`vm_frame_shm.h`）

64 字节定长头 + 3 个等长轮转缓冲（`VM_FRAME_SHM_NBUFS=3`）：

- 写端：`memcpy` 到 `(seq+1)%3` 号缓冲 → 写 `slot/width/height` → `release` 递增 `seq`。
- 读端：`acquire` 读 `seq`；与上次不同即从 `slot` 缓冲拷出。
- 3 个缓冲保证"写端当前写的槽"不会正好是"读端正在读的槽"，因此**无需加锁**、读端也不需要跨帧持有指针。
- `magic`（`'VMFR'`）由写端**最后**写入，作为"已就绪"标志；读端只在 magic 正确时接受，避免读到半初始化/上一轮残留。

预留容量 = 按显示尺寸 `dispW*dispH*4` 向上取整到 4KB；帧比预留大时写端返回 `-1`，上层回退文件路径（正常不会发生，因为显示尺寸固定）。

## 4. 兼容与回退

- **无需改调用方**：`vm_guest_display.c` / `vm_engine.c` 里的接口不变。
- **自动回退**：`frame.shm` 不存在（旧写端、建失败、启动竞态）→ 读端继续用 `frame.rgba` + `frame.seq` 文件协议。
- **灰度/关闭**：想强制回退旧路径，删掉实例目录下的 `frame.shm` 并在写端 …（当前未加环境变量开关；如需，可给 `vmhost_gfx_shm_open` 加一道 `VMHOST_FRAME_SHM=0` 判断）。

## 5. 构建与验证

构建（WSL，和原来一样，改了 glue 需重编 AOSP QEMU）：
```bash
cd ~/vmbuild 2>/dev/null; # 或你的 WORKDIR
WORKDIR=~/vmbuild ./engine/scripts/build_qemu_aosp.sh     # 产出 libqemu_exec.so 到 jniLibs
# 然后正常 gradle 打包
```

验证要点：
1. 启动后看 `console.log` / `qemu-stderr.log` 里有没有：
   `VMHOSTGFX shm: 帧回传共享内存就绪 .../frame.shm（720x1280 stride=... n=3 total=...）`
2. App 日志（`VmFrameRelay`）应出现：`共享内存帧回传就绪：.../frame.shm（disp 720x1280 ...）`。
3. 回传线程首次出帧会打：`VMHOSTGFX frame relay v3(shm): 720x1280 原生 RGBA（零文件 IO）`。
4. 观察 `<dataDir>/logs/` 下**不再滚动生成** `frame.rgba` / `frame.rgba.tmp`（`frame.request`/`frame.seq` 仍可能出现，属正常）。
5. 主观对比：滑动、下拉通知、输入回显的跟手程度。

## 6. 已知边界 / 后续可做

- 显示尺寸运行期可调（`VMHOST_GFX_W/H`）；改尺寸会重建 `frame.shm`（下次启动生效）。
- 读端已做**零拷贝**：`shm_poll` 直接把共享内存槽指针交给 `glTexSubImage2D`，不再单独 memcpy；
  3 缓冲轮转保证写端复用该槽前有 NBUFS 帧余量，调用方在本次调用内上传，安全。
- **逃生舱已实现**：写端设 `VMHOST_FRAME_SHM=0` 即强制回退文件回传（`frame.rgba`+`frame.seq`），
  便于线上排障/灰度对比。
