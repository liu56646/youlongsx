# TCG 地址翻译内联候选

本轮找到一项小幅、可复现的 TCG 页表压力测试收益，但没有证明完整 Android
启动或运行响应改善，未替换手机主引擎。

保留 `regime_el()` 原函数体，仅要求编译器内联，暴露地址翻译过程中重复的
局部 EL/控制寄存器解码。没有新增跨访问缓存，没有改变页表、权限、失效
规则、CPU 状态或快照格式。新构建开关 `VMHOST_TCG_REGIME_INLINE=1` 默认关闭；
切回 0 会从重复使用的源树移除该注解，不会让旧的启用状态悄悄残留。

32768 组实际 LPAE 函数对照中，原实现与候选的成功数、故障数、输出及读取
轨迹摘要相同。它们使用相同的物理总线/QOM 边界模型，不能代替并发整机验证。

另外编写了短时真实 TCG 客体：单核/64 MiB，启用四级页表，执行 8000 次
TLBI，每次访问并校验 32 页。两批独立运行均按 ABBA 三轮执行：

| 批次 | 原引擎中位数 | 候选中位数 |
| --- | --- | --- |
| 首批 | 53.29 ms | 51.76 ms |
| 完整命令复现 | 53.19 ms | 51.64 ms |

该压力区间耗时下降约 2.9%，各次校验和一致，均正常退出。计时区间不包括
引擎和图形初始化。它不是“整机提速 2.9%”，也不能换算成七分钟冷启动将
减少多少秒。测试为 shell/root 域，而非 Android App 域；多核竞争、真实
应用和完整冷启动仍待验证。内联还增加了所选函数的静态指令数，可能影响
其它工作负载，因此暂不默认启用。

另一个“完整 TLB 清空改为 SIMD 缓存写入”的候选未测出值得接入的收益，
已排除；没有继续叠加此前变慢的 bank-skipping 或 TTBR-ASID 实验。

原应用未更新，未打开原实例，没有修改全局测试属性；结束时无测试 QEMU
进程，全部 19 个原实例文件仍与已校验的检查点一致。已知的访客存储绑定
超时问题没有在这项编译优化中宣称解决。
