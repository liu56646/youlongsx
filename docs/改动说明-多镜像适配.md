# 改动说明：多 Android 版本镜像适配

> 目标：同一套引擎按镜像布局自动分流，支持 p11 / p9 / p71 / p13 四套访客。
> 入口仍然是 `VmGuestCatalog.ALL`，下载包仍按 `<base>/<tag>.zip` 约定。

---

## 1. 版本与布局

| tag | Android | system.img | 额外分区 | 输入 | 显示 |
|---|---|---|---|---|---|
| `p11_arm64` | 11 | standalone ext4 | metadata / product / system_ext / vendor | virtio-tablet/keyboard | virtio-gpu + gfxstream |
| `p13_arm64` | 13 | standalone ext4 | metadata / product / system_ext / vendor | virtio-tablet/keyboard | virtio-gpu + gfxstream |
| `p9_arm64` | 9 | GPT（vda1 = system） | vendor（GPT）；data / encryptionkey 为 raw | goldfish-events | goldfish_fb + gfxstream post callback |
| `p71_arm64` | 7.1 | 整盘 ext4 | 无 vendor / metadata | goldfish-events | goldfish_fb → `frame.shm` |

`vm_qemu.c` 的判定顺序：

1. 路径或 marker 命中 `p9_arm64` / `vmhost_guest_p9` → SAR 启动（`root=/dev/vda1`，不下发 initrd）。
2. 路径或 marker 命中 `p71_arm64` / `vmhost_guest_p71` → legacy virtio-mmio + goldfish 输入/显示。
3. `system.img` 偏移 `0x438` 有 ext4 magic → 不下发 legacy DT fstab，使用 ramdisk 自带 fstab。
4. 其余（p9 GPT）→ 下发 legacy DT fstab，按 GPT `by-name` 挂 system/vendor。

p9 和 p71 都走 classic ranchu 的 goldfish_fb/goldfish-events；p11/p13 才使用
virtio-gpu + virtio-input。

### 3.1 p9 vendor 显示属性

p9 的 SDK vendor `init.ranchu.rc` 依赖官方 emulator 的 `qemu-props` 注入
`ro.kernel.qemu.uirenderer/opengles.version/dalvik.vm.heapsize`。VMHost 的
pipe 不提供这组属性时，SurfaceFlinger 会落到旧 HWC overlay，报
`failed to create EGLImage: 0x300c` 并持续重试。打包脚本在 p9 vendor 的
`on post-fs` 里补：

```text
setprop debug.sf.hw 0
setprop ro.sf.hw 0
setprop debug.sf.nobootanimation 1
setprop ro.sf.lcd_density 320
setprop ro.kernel.qemu.uirenderer opengl
setprop ro.kernel.qemu.opengles.version 131072
setprop ro.kernel.qemu.dalvik.vm.heapsize 512m
setprop ro.kernel.qemu.gles 1
setprop ro.kernel.qemu.lcd_density 320
```

这样 SurfaceFlinger 走 GLES 合成，不再依赖 p9 旧 gralloc/HWC 的 EGLImage
路径；p9 实测已 boot_completed，并进入 `SystemServer: StartActivityManager`。
引擎对 p9 同时设置 `VMHOST_GFX_POST=1`：goldfish_fb 桥负责 bootanim，
gfxstream post callback 尝试抓 framework UI。两者共用 `frame.shm`，
这是当前 API 28 旧 guest 的折中路径。

### 3.2 旧 guest 的 gralloc 后端

stock gfxstream 默认 `MINIGBM`；p11/p13 的 allocator@3.0 适用，但 p9/p71
的旧 `libEGL_emulation`/gralloc 必须使用 `GOLDFISH_GRALLOC`。自定义 glue
之前没有调用 `RenderLibImpl::setGrallocImplementation`，导致：

```text
FrameBuffer.cpp: bad color buffer handle ...
FrameBuffer.cpp: Failed to find ColorBuffer:0
SurfaceFlinger: failed to create EGLImage: 0x300c
```

现在 `vm_qemu.c` 对 p9/p71 设置 `VMHOST_GOLDFISH_GRALLOC=1`，glue 在
`android_setOpenglesEmulation` 前选择 `GOLDFISH_GRALLOC`；p11/p13 继续
`MINIGBM`。修复后 p9 qemu-stderr 不再出现上述 color buffer/EGLImage 错误，
并进入 `SystemServer: MakeDisplayReady`。

另外 p9 SDK 的 `init.ranchu-net.sh` 会无限重启 `dhcpclient_def`，而本引擎
没有可用网卡；`make_guest_image.sh` 现在同时移除 `ranchu-net` /
`dhcpclient_rtr` / `dhcpclient_def` 服务。

## 2. p9：FDE 的 vdd 不能省

p9 的 vendor fstab：

```text
/dev/block/vdc  /data  ext4  ...  wait,check,quota,forceencrypt=/dev/block/vdd,...
```

因此盘序必须是：

```text
vda = system (GPT vda1)
vdb = vendor (GPT vdb1)
vdc = data
vdd = encryptionkey
```

引擎按 `encryptionkey → data → vendor → system` 的顺序添加 virtio-blk，ranchu 的
virtio-mmio 盘符是反序，最终正好得到上表。

- `tools/make_guest_image.sh` 会在 p9 包里补 16MB `encryptionkey.img`。
- App 创建实例时把它复制成 `<vmDir>/encryptionkey.img`，**每个实例一份**；
  FDE key/footer 不能跨实例共享。
- p9 的 4GB userdata 只启用 `quota` ext4 特性。p9 的 4.4 内核支持
  `quota`（0x100），但不支持 `project`（0x2000）；带 `project` 会让 `/data`
  挂载报 `unsupported optional features (2000)`。

## 3. p9/p71：classic ranchu goldfish

p71 的 Linux 3.18 不支持 modern virtio-mmio，启动参数加：

```text
-global virtio-mmio.force_legacy=on
-global goldfish-events.have-touch=on
-global goldfish-events.have-multitouch=off
-global goldfish-events.have-keyboard=on
```

QMP 触摸对 p9/p71 使用 `btn left`（goldfish-events 的 legacy absolute mouse handler
会把它翻译成 `ABS_X/Y + BTN_TOUCH + SYN`），p11/p13 仍使用 `btn touch`。

显示走 `ui/vmhost_goldfish_fb.c`：注册 `DisplayChangeListener`，把 goldfish_fb
surface 转成 RGBA8888 写入共享内存 `frame.shm`。注册时主动发布一次整帧，
分辨率切换时也整帧重发，避免 relay 第一次 mmap 晚于首帧而一直黑屏。

`frame.shm` 可能被上一次更大分辨率的 VM 留下（例如 800x600 复用 720x1280 的
11MB 文件）。写端必须按 header 里的 `stride_cap` 映射整个文件，不能只 mmap
本次尺寸算出的 total，否则第 2/3 个轮转缓冲会越界 SIGSEGV。

`goldfish_fb_set_use_host_gpu()` 在 `VMHOST_GOLDFISH_FB=1` 时强制关闭 host-GPU
路径，否则 `goldfish_fb_write()` 会在调用 `graphic_hw_update()` 前返回，帧永远不更新。

## 4. p13：APEX self-test 与机型身份

- p13 的 SDK system 镜像没有 `/apex/com.android.conscrypt/bin/boringssl_self_test64`，
  但 `/system/etc/init/hw/init.rc` 会在 `apexd.status=ready` 时 exec_start 它，
  并带 `reboot_on_failure`。实测普通 system BoringSSL self-test 成功，只有
  APEX 触发失败并 reboot（`boringssl-self-check-failed`）。
  `build_p13_image.sh` 现在会注释掉两条 APEX exec_start，保留正常 system 自检。
- p13 的 product build.prop 没有 `# begin` 段标记。`VmDeviceIdentity` 增加
  整文件同长度改写：从 `# from generate-common-build-props` 文件头定位，
  改写身份行，用头部 `#` 注释补齐/缩短，文件大小和 ext4 extent 不变。
- profile 的 fingerprint 是 Android 11 的 Pixel 4；p13 镜像版本不匹配时，
  保留镜像的 Android 13 build 后缀，只替换 `brand/name/device` 前缀，并保留
  镜像的 `ro.build.id`。实测 p13 实例：
  - product: `ro.product.product.model=Pixel 4`，fingerprint
    `google/flame/flame:13/TE1A.220922.034/...`，文件仍 2757B。
  - system: `ro.product.system.*` 全部换成 Pixel 4 值，`ro.system.build.fingerprint`
    同为 Android 13 Pixel，文件仍 4456B。

## 5. 当前限制

- p71 的 `init` 是 Android 7.1 的 fs_mgr，**没有** `resize` 这个 fstab flag；
  `make_guest_image.sh` 在打包阶段先 `truncate -s 4G` + `resize2fs`，所以
  `/data` 模板本身就是 4GiB，不需要 guest 端 resize。
- p9 的 userdata 模板是 4GiB，首次导入/建实例会做一次完整拷贝；后续可改为
  1MiB 占位 + vendor fstab `formattable` 来降低 I/O。
- p9 首次启动会执行 FDE（`forceencrypt=/dev/block/vdd`），需要 encryptionkey
  盘；当前实测在 `-no-reboot` 下也能完成 enablecrypto 并继续启动。
- **p9/p71 launcher 还需最终 UI soak**：`GOLDFISH_GRALLOC` 已修复旧 guest
  的 color buffer/EGLImage 错误，p9 能 boot_completed 并进入
  `SystemServer: MakeDisplayReady`；但最后一次 launcher 截图验证被宿主锁屏/
  测试 index 干扰，尚未拿到干净 p9/p71 launcher 截图。p9 的 `frame.shm`
  在部分运行中仍停在初始 goldfish 帧，需要继续做一轮不锁屏、干净 userdata 的
  SystemUI/launcher soak。p71 同样需要这轮验证。
