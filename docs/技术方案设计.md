# 游龙沙箱 —— 自研 Android 系统虚拟机 技术方案设计

> 目标形态：在 Android 手机上运行一个**完整的访客 Android 系统**（QEMU 型），
> 支持多实例、可视化交互、免 root。参考对象为 `com.vphonegaga.titan` 的架构模式，
> 但其 native 引擎、系统镜像、Wine 资产均为其私有产物，**不复制、不复用**。

---

## 1. 目标与范围

### 1.1 目标

| 编号 | 目标 | 验收口径 |
|---|---|---|
| G1 | 真机上启动访客 Android 系统 | 看到访客开机动画并进入桌面 |
| G2 | 可交互 | 宿主触摸/按键 → 访客系统响应 |
| G3 | 有网络 | 访客内可联网（HTTP 可达） |
| G4 | 有声音 | 访客音频在宿主扬声器播放 |
| G5 | 多实例 | 至少同时运行 1 个，可切换/停止 |
| G6 | 持久化 | 实例数据落盘，重启后保留 |

### 1.2 非目标（本期不做）

- 跑 Windows / Wine（`wine_data` 属其私有资产，且工程量独立）
- GPU 硬件直通级别的 3D 加速（先做 OpenGL ES 软/半软渲染）
- 云端分发、账号体系、计费
- 机型伪装、反检测等对抗性能力

### 1.3 合规边界（硬约束）

- **不使用**参考应用的 `libVPhoneGaGaLib.so`、`libuserkernel*.so`、`androidfs_*.7z`、`wine_data` 等任何二进制或镜像；
- 访客系统镜像由 **AOSP 自行编译**；
- QEMU 为 **GPLv2**，链接进 App 会触发 GPL 传染 —— **已决策：引擎（含我们对 QEMU 的修改）以 GPLv2 开源**（见 §8.2）；
- 参考应用只作为**架构模式参考**（组件划分、进程模型、原生模块命名约定），代码全部重写。

## 2. 总体架构

```
┌───────────────────────────────────────────────────────────────┐
│ L1 宿主 UI 层（主进程）                                        │
│   机器列表 / 启动器 / 设置 / 文件互传 / 镜像下载                │
│   Activity + Fragment + ViewModel（Kotlin，无计费模块）        │
└───────────────┬───────────────────────────────────────────────┘
                │ Binder (AIDL IVPhoneManager)
┌───────────────▼───────────────────────────────────────────────┐
│ L2 实例管理层（主进程）                                        │
│   VmManager：实例生命周期、镜像/磁盘配额、进程编排             │
│   VmNetworkService：VpnService（宿主侧 tun）                   │
│   VmAlarmReceiver：定时/保活                                   │
└───────────────┬───────────────────────────────────────────────┘
                │ Binder (AIDL IVmInstance) + 启动 :vmN 进程
┌───────────────▼───────────────────────────────────────────────┐
│ L3 实例运行时（每实例独立进程 :vmN）                           │
│   VmNativeActivity（NativeActivity，持有宿主 Surface）         │
│   VmInstanceService（前台服务，保活 + 输入分发）               │
│   ── JNI ──►  libvmengine.so（QEMU 引擎封装）                  │
│                 ├─ QEMU system-mode (aarch64-softmmu)          │
│                 ├─ 渲染后端 libvmrender.so（OpenGL ES → Surface）│
│                 └─ 镜像加载 loader（qcow2 / overlay）           │
└───────────────┬───────────────────────────────────────────────┘
                │ virtio：gpu / input / net / blk / snd
┌───────────────▼───────────────────────────────────────────────┐
│ L4 访客系统层（自编译 AOSP 镜像）                              │
│   kernel(ranchu) + system.img + vendor.img + ramdisk           │
│   访客内为完整 Android，拥有自己的 PMS/AMS/桌面/应用            │
└───────────────────────────────────────────────────────────────┘
```

| 层 | 进程模型 | 关键职责 | 主要技术 |
|---|---|---|---|
| L1 宿主 UI | 主进程 | 机器管理、启动、设置 | Kotlin / RecyclerView / Room |
| L2 实例管理 | 主进程 | 编排、磁盘、网络代理 | AIDL / VpnService / WorkManager |
| L3 实例运行时 | `:vmN` 独立进程 | 承载 QEMU、渲染、输入 | NativeActivity / JNI / EGL |
| L4 访客系统 | QEMU 内部 | 完整 Android 系统 | AOSP / ranchu kernel / virtio |

> 为什么要**每实例独立进程**：QEMU 是单实例全局态（信号、线程、地址空间），进程隔离可避免崩溃互相污染，便于按实例 OOM 回收，也让 `NativeActivity` 能各持一个独立 `Surface`。

## 3. 关键技术选型

### 3.1 虚拟化内核：QEMU（system mode）+ TCG/MTTCG

- **选 QEMU system mode**（`qemu-system-aarch64`）：唯一能跑"完整 Android 系统"的开源方案。
- **无 KVM**：手机 `/dev/kvm` 基本不可用（需 root + 特定内核），因此走 **TCG 软件翻译**；启用 **MTTCG**（多线程 TCG）用满多核。
- 同构假设：**宿主 arm64 → 访客 arm64**。同构 TCG 仍要翻译，但可用更快路径；若 guest 为 x86_64 则全量翻译，性能再降一档，**本期只做 arm64 guest**。
- 备选/对照：Bochs（LGPL 但太慢）、纯 `proot`（不是虚拟化，语义不同）——均不满足"完整系统"目标。

### 3.2 ABI 策略

| 项目 | 取值 | 说明 |
|---|---|---|
| 宿主 ABI | `arm64-v8a` 优先 | 目标真机基本是 arm64 |
| 引擎 ABI | `arm64-v8a` / `x86_64`（模拟器调试用） | 交叉编译两套 |
| 访客 ABI | `arm64-v8a` | 仅同构，保证可用性能 |
| minSdk | 28 | glib 依赖 bionic 的 `iconv`，该符号 API 28 起提供（见 §A.6） |

### 3.3 访客系统镜像：自编译 AOSP

- 基于 **AOSP + `ranchu`（emulator）内核**：ranchu 就是为"虚拟化运行"设计的，默认带 virtio 驱动。
- 内核需裁剪：保留 `virtio_gpu / virtio_input / virtio_net / virtio_blk / virtio_snd / ext4 / overlayfs`，去掉无关驱动。
- 产物：`kernel` + `ramdisk.img` + `system.img` + `vendor.img`（可只出 system+vendor 以省体积）。
- 版本策略：**首发 Android 11（R）**。镜像更大、内存与启动开销更高，M0/M1 阶段需优先验证低配真机上的启动时间与帧率；若性能不达标，回退 Android 9 作为降级档。
- 体积控制：镜像用 7z/romfs 压缩随包分发，首启解压到实例目录（参考应用也是这个套路，但我们用自产镜像）。

### 3.4 图形显示链路

```
guest App 渲染
   → guest SurfaceFlinger（virtio-gpu 后端）
   → QEMU virtio-gpu 设备
   → 引擎渲染后端 libvmrender.so
   → EGL/OpenGL ES 绘制到宿主 Surface
   → 宿主 VmNativeActivity 上屏
```

- 先用 **virtio-gpu + OpenGL ES 渲染到宿主 `Surface`**（`ANativeWindow` → `eglCreateWindowSurface`）。
- 参考应用用 `libOpenglRender.so` 承担这一段，我们自写一个精简渲染后端。
- 帧同步：guest 侧 vsync 由引擎按宿主 `ASurfaceControl`/`Choreographer` 节拍驱动。

### 3.5 输入

- 宿主 `MotionEvent` / `KeyEvent` → JNI → 注入 QEMU **virtio-input** 设备 → 访客 `evdev`。
- 触摸坐标需做分辨率映射（宿主 Surface 尺寸 ↔ 访客屏幕尺寸）。
- 键盘/软键盘：宿主 IME → `KeyEvent` → virtio-keyboard。
- 参考应用支持手柄映射（`assets/kb_map/*`），属后续增强。

### 3.6 网络

**当前实现：QEMU 内置的用户态 NAT（slirp）**

- 访客侧：`virtio-net-pci`，DHCP 拿到 `10.0.2.15`，网关 `10.0.2.2`，DNS `10.0.2.3`
- 引擎侧：`-netdev user,id=net0`，slirp 在 QEMU 进程内把访客的 TCP/UDP 转成宿主 socket
- 优点是**零宿主权限**：不需要 `VpnService`、不需要 VPN 授权

**为什么没走 VpnService（§2 最初的设想）**

`VpnService` 拿到的是**应用侧** tun fd，QEMU 无法直接当网卡用。要让它工作，
引擎里必须自己实现一套用户态 NAT：应答访客的 ARP、改写源地址为 tun 地址、
重算 IP/TCP/UDP 校验和。工作量和出错面都远大于直接用 slirp，因此先放后。
`VmNetworkService` 保留在工程里，留给以后需要「访客流量完整走宿主网络栈」
（例如按应用分流、抓包、Socks5 出口）的场景。

### 3.7 音频

- guest → `virtio-snd` → 引擎 → 宿主 `AudioTrack`（低延迟可用 Oboe）。
- 先做单向播放，录音（麦克风回传）二期。

### 3.8 存储

- 每实例一个目录：`instance_<id>/`，内含 `system.img`（只读共享）、`userdata.qcow2`（可写）。
- 用 **qcow2 overlay**：基础镜像只读，增量写 overlay，实现秒级"新建机器 / 重置机器"。
- 快照：直接保留 overlay 文件即天然快照。

### 3.9 原生模块分发与 Android 限制（关键坑）

Android 10+ 对 App 私有目录有 **W^X / noexec** 限制，**不能直接 exec 家目录里的可执行文件**。对策（参考应用正是这么做的）：

- 把原生可执行体打包为 **`lib*.so`** 放进 `jniLibs`，安装后被解压到 `nativeLibraryDir`（该目录可执行）；
- `AndroidManifest` 中 `android:extractNativeLibs="true"`；
- `useLegacyPackaging = true`（AGP 8+ 必须显式开，否则 so 不解压）；
- 引擎入口以 `android.app.lib_name` meta-data 指向 `libvmengine.so`，配合 `NativeActivity` 运行。

| 模块 | 形态 | 职责 |
|---|---|---|
| `app` | Android App | L1 UI + L2 管理，主进程 |
| `:core-vm` | Kotlin library | 实例配置模型、AIDL 契约、磁盘管理 |
| `:engine-api` | Kotlin library | JNI 接口声明、引擎配置构建 |

| `:guest-image` | 构建产物 | AOSP 镜像（独立仓库/流水线，不进 App 仓库） |

**L2 核心类**

- `VmManager`：`createVm(config)` / `startVm(id)` / `stopVm(id)` / `deleteVm(id)` / `listVms()`
- `VmDiskStore`：qcow2 overlay 的创建/复制/删除、空间统计
- `VmImageProvider`：镜像解压、校验（sha256）、版本管理
- `VmNetworkService`：tun 建立与路由，供引擎 slirp 使用

## 5. 启动时序（数据流）

```
宿主 UI         VmManager        :vmN 进程          引擎(JNI)         访客系统
   │                │                │                  │                │
   │ startVm(id)    │                │                  │                │
   ├───────────────►│                │                  │                │
   │                │ 校验镜像/磁盘   │                  │                │
   │                │ 启动服务进程 ──►│                  │                │
   │                │                │ 启动 NativeActivity│                │
   │                │                │ surfaceCreated ──►│                │
   │                │                │                  │ 初始化 QEMU    │
   │                │                │                  │ 加载 kernel ──►│
   │                │                │                  │ 挂载 system    │
   │                │                │◄─ 首帧渲染 ──────┤◄─ SurfaceFlinger│
   │◄── 画面显示 ────┴────────────────┤                  │                │
   │ 触摸事件 ──────────────────────►│── 注入 virtio-input ──────────────►│
   │                │                │                  │◄─ 网络/音频 ────┤
```

关键节点：**Surface 就绪**是启动引擎的触发点；**首帧**是"启动成功"的判据；`stopVm` 走 `NativeActivity.onStop` → 引擎 `pause/save` → 杀 `:vmN` 进程。

## 8. 风险与对策

### 8.1 性能（最高风险）
- 无 KVM → TCG 翻译开销大，开机可能数十秒、界面帧率偏低。
- 对策：MTTCG 多核；guest 只保留必要服务（裁 AOSP）；渲染后端做**脏区更新**而非全屏重绘；镜像预解压 + 快照秒起。

### 8.2 许可证（必须尽早决策）
- QEMU 为 **GPLv2**，动态链接进 App 亦触发 GPL 传染。
- **已决策：接受 GPL 传染，`engine` 模块（含对 QEMU 的修改、渲染后端、loader）以 GPLv2 开源**；宿主 App 的 Java/Kotlin 层（UI、管理器、业务）保持闭源。
- 执行要求：仓库层面把 `engine` 拆成**独立模块/独立仓库**，GPL 边界写在模块根目录；App 闭源部分**不得**静态或动态链接进 GPL 模块之外，避免边界模糊导致整包被要求开源。

### 8.3 Android 平台限制
- W^X / noexec（§3.9）、SELinux、隐藏 API 收紧、前台服务类型强校验（Android 14+）。
- 对策：so 化分发、`foregroundServiceType` 显式声明、避开非 SDK 接口。

### 8.4 资源与稳定性
- 多实例内存叠加会 OOM；QEMU 崩溃会带走整个 `:vmN`。
- 对策：限制并发实例数；实例进程独立；崩溃自愈重启。

### 8.5 镜像分发
- 镜像体积大、下载慢；需断点续传 + 校验。

| 阶段 | 内容 | 出口标准 |
