# 外部 Android 镜像导入与适配

App 的「导入外部 Android 镜像」接收 ZIP，归一化目录及文件名、展开 Android
sparse 分区，并为每次导入分配独立镜像目录。导入后的系统出现在新建实例列表。
原有镜像、实例磁盘、快照不被替换。外部系统默认不做设备身份改写。

**当前还不能保证“大部分手机刷机包可以开机”。** 容器/分区转换不等于硬件适配。
引擎目前是 ARM64 QEMU ranchu；手机 boot/kernel、vendor HAL、图形驱动和设备树
通常面向特定手机，不能作为 ranchu 组件直接使用。Android-x86、其他虚拟机的
专有硬件和加密格式也不能通过改后缀兼容。

## 目前覆盖的封装

| 输入 | 处理方式 | 边界 |
| --- | --- | --- |
| 已适配 ARM64 ranchu ZIP，含子目录 | App 直接导入 | 检查组件、内核架构、分区头；仍需启动实测 |
| raw/ext4、Android sparse 分区 | App ZIP 内自动展开；电脑工具也可转换 | sparse v1 的 RAW/FILL/DONT_CARE/CRC32 结构；不校验可选 sparse 校验和 |
| fastboot ZIP、TAR/TGZ、镜像目录 | 电脑工具提取所需组件 | 忽略刷机脚本和其他文件，不执行包内程序 |
| Pixel factory ZIP（内套 `image-*.zip`） | 电脑工具读取内层 ZIP | 只展开一层；`system_other`、`userdata_exp` 等不收集 |
| 单独 `.img`、`.img.xz`、`.img.gz` | 电脑工具读取/解压 | 缺少虚拟硬件组件时不能独立启动 |
| 完整 OTA `.new.dat` | 电脑工具按 transfer.list 重建 | 仅 full new/zero/erase；增量 move/bsdiff/stash 明确拒绝 |
| `.new.dat.br` | 电脑工具调用已安装的 `brotli` | 之后同上 |
| `payload.bin` | 电脑工具调用已安装的 `payload-dumper-go` | 工具必须能完整提取；增量包仍需要原分区 |
| `super.img`（raw/sparse） | 电脑工具内置解析 LP 元数据，边读边写出逻辑分区 | 不落地整个 super、不需要 lpunpack；校验元数据 SHA-256；按 A/B 槽选择；只导出 system/vendor/product/system_ext，单设备 super |
| `super.img_sparsechunk.N`（Motorola） | 按序号依次流式解析，同上 | 序号必须从 0 连续；缺块拒绝 |
| 独立 qcow2 分区 | 调用已安装的 `qemu-img` 转 raw | 拒绝 backing/external-data/encrypted；全系统盘还需适配分区布局 |
| EROFS 的 system/system_ext/product/vendor | `prepare` 时只读挂载，用 `mke2fs -d` 直接重建为 ext4（App 与访客 fstab 只挂 ext4） | 需在 Linux 下以 root 运行（WSL 可），要有 mount 与 e2fsprogs；Windows 上会提示改用 WSL。属主、权限、xattr（SELinux 标签、capability）、符号链接、硬链接、文件内容逐项比对一致才使用；`lost+found` 按 Android 惯例沿用根目录标签 |
| x86/ISO、VMDK/VDI、专有加密包 | 当前不直接启动 | 不靠改后缀兼容 |

可选工具缺失时明确显示工具名称，不会下载或运行刷机包中的脚本。外部工具的
支持范围取决于其版本，当前测试没有覆盖所有真实 payload/super 变体。

## 电脑工具

Python 3.9+，标准库；可选提取工具放到 PATH。先查看封装：

```powershell
python vm/tools/import_android_image.py inspect D:/ROM/rom.zip
```

将已经适配的虚拟机组件重新打包（不会覆盖已有输出）：

```powershell
python vm/tools/import_android_image.py prepare D:/ROM/virtual-images --profile p11 --name "第三方 Android" --output D:/ROM/third-party.zip
```

选择 B 槽时加 `--slot b`，默认 A 槽。`inspect` 只识别输入，不执行可选提取工具。
`prepare` 输出可在手机 App 中导入的 ZIP。若输入只有手机分区，会报告缺少的
虚拟机组件，不会把手机 boot.img 当作虚拟机内核。

### 实验性 system 替换

已有适配好的虚拟平台模板时，可显式尝试外部 system 与该平台的配套关系：

```powershell
python vm/tools/import_android_image.py prepare D:/ROM/rom.zip --profile p11 --base D:/ROM/adapted-p11 --experimental-system-replacement --name "外部系统实验" --output D:/ROM/experimental.zip
```

工具保留 base 的虚拟内核、ramdisk、vendor，以及新实例用的 userdata/metadata
模板，替换 system.img；外部包若带 system_ext.img、product.img，也一并替换（Treble
里它们和 system 同属系统侧，含 SystemUI 等框架扩展和对应的 sepolicy，需成套使用），
没带的沿用 base 的。不会复制手机的加密数据盘或手机
vendor。base 必须是只读镜像模板，不是带 snapshot.state/snapshots 的实例目录。

这个方法仅提供独立试验路径，**没有证明手机 ROM 的兼容性**。system 与虚拟
vendor 的 Android/VNDK 版本、SELinux 策略、system/product 拆分及厂商服务都
可能需要修改。不能把“转换完成”或“导入完成”当成开机通过。

## ZIP 布局描述

可在包根目录或共同子目录放 `vmhost-image.properties`，Java Properties 格式：

```properties
schema=1
arch=arm64
board=ranchu
profile=p11
api=30
name=Third-party Android
experimental=true
```

`profile` 为启动布局，不是更改系统版本的开关：

| profile | 必需组件 |
| --- | --- |
| p11 / p13 | kernel、ramdisk.img、system/vendor/product/system_ext/userdata/metadata.img |
| p9 | kernel、GPT system.img、vendor.img、userdata.img、encryptionkey.img |
| p71 | kernel、ramdisk.img、system.img、userdata.img |

`kernel-ranchu` / `kernel-ranchu-64` 归一为 kernel；kernel 必须是 ARM64
Linux Image（raw 或 gzip，gzip 会校验完整解压流）。p9/p71 导入时生成对应
启动标记，因此重命名后的镜像仍可走原布局。
没有描述文件的旧包可通过 p9/p71 标记识别，否则按 p11 布局检查。

分区通常要求 ext4；p9 system 要求 GPT，vendor 允许原有 GPT。userdata 必须
是可用模板；p11/p13 也接受 SDK 的 1 MiB 全零占位模板（由配套 fstab 在首次
启动格式化），其他大小的无文件系统数据盘会拒绝。App 保留大于默认 4 GiB
的模板完整长度。文件头
检查仅用于尽早发现格式错误，不验证全部文件系统结构或内核硬件驱动。

## 保护现有实例

导入先解压/检查到随机临时目录，再发布到 `images/external_<随机标识>`；失败清理
临时内容。重复导入产生不同标识。已导入的基础镜像不被后续导入替换，避免与
旧 RAM 快照配对出错。每个实例的 userdata、metadata、vmstate 和快照仍独立。

没有闲置实例号时，可以先导入，之后从「新建实例」选择该镜像。不要为了试验
直接改现有实例的 imageTag，也不要把别人的 RAM 快照和本机磁盘混用。

## 验证

- JVM 测试覆盖 sparse 短读/溢出、RAW/FILL/空洞、路径越界、重复架构、错误内核、
  缺盘、p9 GPT 和 p71 无 vendor 等情况。
- Python 测试覆盖分区转换、完整/增量 OTA 区分、qcow2 backing 拒绝、输出不覆盖、
  实验拼装不修改 base、保留虚拟 vendor/干净数据模板等。
- 设备测试使用独立测试 APK：验证原子导入、重复导入、失败清理、已有目录保护及
  大数据盘长度保留。测试夹具不是可启动 Android 系统。
- 未取得真实第三方手机 ROM 样本并完成桌面、触控、网络等回归前，不报告其兼容。
