# 锚点收敛手册

> 换 AOSP QEMU / gfxstream 大版本时，补丁会"失配"。本手册讲清楚**锚点是什么、怎么一步步重新对齐**，配合 `anchor_tools/` 里的两个脚本用。
> 上层路线见 `QEMU基座升级-移植指南.md`；本文件只管"具体怎么把每个锚点啃下来"。

---

## 0. 一句话

**锚点 = 补丁脚本里 `src.replace(old, new, 1)` 里那段精确源码文本。**
收敛 = 让每个补丁的 `old` 在新源码树里**重新命中且只命中一次**。

---

## 1. 锚点长什么样

你现在的补丁全是"文本锚点"式，例如：

```python
# patch_ranchu_pcie.py
def rep(old, new, cnt=1):
    n = src.count(old)
    if n != cnt:
        print("!! anchor 命中 %d 次（期望 %d）:\n%s" % (n, cnt, old[:200]))
        sys.exit(2)          # ← 失配就在这里退出
    src = src.replace(old, new, cnt)

rep('    create_gic(vbi, pic);\n',                       # ← 这就是"锚点"
    '    create_gic(vbi, pic);\n'
    '    create_pcie(vbi, pic);\n')
```

`build_qemu_aosp.sh` 里的内联补丁同理，用 `perl -0pi -e 's/.../.../'` 或 Python heredoc，`s/OLD/NEW/` 的 `OLD` 就是锚点。

**锚点命中 ≠ 补丁正确，只说明"这段代码还在"。** 命中失败（0 次或 >1 次）才是需要处理的信号。

---

## 2. 为什么会失配

换版本后上游动了那段代码，锚点就失配。三种情形，处理成本递增：

| 情形 | 现象 | 处理 |
|---|---|---|
| **文本微调** | 同一函数还在，只是空行/参数/一行变了 | 最省事：把 `old` 改成新文本 |
| **搬家/改名** | 函数或字段换名、挪到别的文件 | 找到新位置，重写锚点（下面 §4） |
| **被删/重构** | 整段代码没了（如 `register_savevm` 废除） | 补丁要**重新设计**，不是改字符串 |

---

## 3. 收敛循环（一次只啃一个）

```bash
cd ~/vmbuild                      # 你的构建工作目录
export SRC_DIR=~/vmbuild/qemu-aosp
export GFX_DIR=~/vmbuild/gfxstream

# ① 全局看进度：哪些锚点还在、哪些失效
python3 /path/to/vm/engine/scripts/anchor_tools/probe_anchors.py

# ② 选中一个 ❌，跑构建或单跑该补丁，看它打印的"锚点命中 N 次"
WORKDIR=~/vmbuild ALLOW_UNVERIFIED_QEMU=1 ./engine/scripts/build_qemu_aosp.sh
#    （或单独跑某个 py 补丁：python3 engine/scripts/qemu_patches/patch_xxx.py $SRC_DIR）

# ③ 用 find.sh 去新源码里定位等价代码
./engine/scripts/anchor_tools/find.sh $SRC_DIR 函数名或宏名

# ④ 把新代码段抄回补丁脚本的 old/new —— 改完重跑，回到 ②
#    一个补丁绿了再下一个；不要一次改多个
```

`build_qemu_aosp.sh` 的补丁是幂等的（靠 `MARK` 字符串判断"已应用就跳过"），所以**反复重跑是安全的**：每改好一个锚点，重跑会自动跳过已应用的、只对没命中的继续报错。

## 4. 怎么定位"等价代码"（关键技能）

换版本后，**函数名/宏名是最稳定的搜索键**（上游很少改函数名，改的是函数体）。用 `find.sh`：

```bash
# 例：virtio-gpu capset 补丁失配，去找 virgl_cmd_get_capset_info 现在长啥样
./engine/scripts/anchor_tools/find.sh $SRC_DIR virgl_cmd_get_capset_info
```

它会列出所有命中点，并打印首个命中的 ±25 行上下文 —— 你直接**从上下文里挑一段新的 `old`** 抄回补丁。

搜索键优先级：
1. **函数名**（`virgl_cmd_get_capset_info`、`create_pcie`、`virtio_gpu_set_features`）——最稳；
2. **宏/类型名**（`RANCHU_MMIO`、`CONFIG_STREAM_RENDERER`、`VirtBoardInfo`）；
3. **结构体字段附近**（`clock_phandle`）；
4. 实在没有，才用**唯一语句**做锚点（如 `    create_gic(vbi, pic);`）。

找不到符号时，多半是**搬家**了：`grep -rn` 整个树找同义串，或去上游的 `git log -S"符号"` 看它被移到哪。

---

## 5. 重写锚点的四条原则

1. **最小**：锚点只覆盖"你要改的那几行"，别整函数抄。整函数做锚点，上游随便改个注释就失配。比如 `patch_virtio_gpu_capset.py` 的 `OLD_INFO` 抄了**整个** `virgl_cmd_get_capset_info` —— 天然脆；重表达时把它缩成"函数签名 + 紧邻的 `memset(&resp, ...)` 那两行"就够定点了。
2. **唯一**：`count == 1`。若新写法在整个文件里出现多次，加上下文行直到唯一。
3. **语义稳定**：锚在**不会因版本变化而变的东西**上（函数名、`#ifdef` 块头、结构体定义），别锚在会被上游顺手改的空行/注释/局部变量名上。
4. **优先"插入"而非"整段替换"**：能加一行就别替换一坨。像 patch H（`create_gic(...)` 后插一行）几乎不会失配；整段 replace 几乎必然要维护。新补丁尽量向这个风格靠。

> 进阶：锚点也可以写成**正则**（`perl -0pi -e 's/.../'` 本就支持），把易变的空行/缩进用 `\s` 吸收，能显著提高跨版本命中率。

## 6. 逐补丁速查表（换版本后照这个顺序攻）

**先易后难**：结构体/单行插入类先做，virtio-gpu + gfxstream 那批最后做。

| 补丁 | 根 | 目标文件 | 稳定搜索键 | 现代变化提示 |
|---|---|---|---|---|
| feature_include / bionic / crash_hooks | qemu | `vl.c` | `qemu/osdep.h` / `pty.h` / `main_impl(` | vl.c/入口在 5.0+ 大改，锚点需按新入口重找 |
| embed_entry | qemu | `vl.c` | `vmhost_qemu_main` | 上游入口在 `softmmu/main.c` + `qemu_init()` |
| goldfish_pipe(_savevm/_arch) | qemu | `hw/misc/goldfish_pipe.c` | `goldfish_pipe` | 用现代 AOSP 分支该文件已更新，补丁可能整个删 |
| virtio_gpu_cursor | qemu | `hw/display/virtio-gpu.c` | `update_cursor_data_virgl` | 2D 路径，多半仍需 |
| virtio_gpu_trace | qemu | `hw/display/virtio-gpu.c` | `virtio_gpu_set_features` | |
| virtio_gpu_stream | qemu | `hw/display/virtio-gpu-3d.c` | `CONFIG_STREAM_RENDERER` | 现代 virgl 拆到 `virtio-gpu-virgl.c`，**重点攻** |
| virtio_gpu_capset | qemu | `hw/display/virtio-gpu-3d.c` | `virgl_cmd_get_capset_info` | 同上，**重点攻** |
| ranchu_pcie | qemu | `hw/arm/ranchu.c` | `RANCHU_MMIO` / `create_gic` | 若现代分支已带 PCIe 则删 |
| vmhost_display_hook | qemu | `ui/console.c` | `graphic_console_init` | `DisplayChangeListener` 新增字段，注意对齐 |
| mmap_alloc | qemu | （全树） | `qemu_memalign` | 内存分配 API 变化 |
| surface_makecurrent | gfx | `host/gl/glestranslator/EGL/EglOsApi_egl.cpp` | `createPbufferSurface` / `makeCurrent` | gfxstream 同名文件大体还在 |
| threadinfo / processpipe | gfx | `host/RenderThreadInfo.cpp` … | `RenderThreadInfo` | 与 gfxstream 分支线对齐 |
| colorbuffer_diag / framebuffer_diag | gfx | `host/gl/ColorBufferGl.cpp` … | `Blit` / `getScreenshot` | 诊断补丁，可先跳过不影响功能 |

（`probe_anchors.py` 会按这张表逐个报状态。）

## 7. 常见坑

- **命中 0 次**：锚点文本不对 —— 用 `find.sh` 抄新文本。注意**中文注释、缩进（空格/Tab）、CRLF** 都算进锚点；抄的时候连注释一起抄。
- **命中 >1 次**：锚点太短/太通用 —— 加上下文行凑唯一。
- **改完还报旧错**：补丁是幂等的，可能**上一轮半途写坏**了文件。先 `git -C $SRC_DIR checkout -- <file>` 还原（`reset_scratch_sources` 已对 vl.c / goldfish_pipe.c 做了，其他文件手动还原），再重跑。
- **perl 与 python 混用**：`vl.c` 那几处是 `perl -0pi -e`（`-0` 表示把整文件当一个串，`.` 能跨行）；改锚点时注意 `\s`、`\n` 的转义，别用普通 grep 的直觉。
- **改了标记串**：每个补丁靠 `MARK` 判断幂等，重表达锚点时**别动 MARK**，否则会重复应用。
- **顺序**：`reset_scratch_sources`（git 还原）必须在前，否则你的改动会被它冲掉。

## 8. 完整示例：重表达 `patch_ranchu_pcie.py` 的调用锚点

假设新版的 `ranchu_init()` 里 `create_gic` 变成带版本参数：

```bash
# 1) 先看现在的样子
./engine/scripts/anchor_tools/find.sh $SRC_DIR create_gic
#   输出里看到：
#     hw/arm/ranchu.c:412:    create_gic(vbi, pic, arch_type);
```

```python
# 2) 把锚点文本改成新样子（patch_ranchu_pcie.py 里的最后一段 rep）
rep('    create_gic(vbi, pic, arch_type);\n',              # ← OLD 更新为新文本
    '    create_gic(vbi, pic, arch_type);\n'
    '    create_pcie(vbi, pic);\n')                        # ← NEW 保持"加一行"的思路
```

```bash
# 3) 重跑该补丁（或整脚本），它不再在 create_gic 处报错 —— 该锚点收敛完成
python3 engine/scripts/qemu_patches/patch_ranchu_pcie.py $SRC_DIR
```

先还原再改（`git -C $SRC_DIR checkout -- hw/arm/ranchu.c`），免得上一轮的半成品干扰。

## 9. 配套工具

| 工具 | 作用 |
|---|---|
| `anchor_tools/probe_anchors.py` | 一次性看全部补丁的锚点状态（✅/❌/✔已应用） |
| `anchor_tools/find.sh` | 在源码树里搜关键字 + 打印上下文，用来抄新锚点 |
| `anchor_tools/anchors.txt` | 锚点清单（可随时补条目） |

换版本 → `probe_anchors.py` 拿 ❌ 清单 → 逐个 `find.sh` + 重表达 → 重跑 → 循环。
